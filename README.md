# 台股營收成長追蹤系統

> 每日自動收集上市櫃約 1,800 家公司的月營收、季報與重大訊息，篩出「基本面正在成長、但股價尚未反映」的標的，並用回測驗證這些訊號到底有沒有用。

營收與財報是**落後指標**。這套系統的價值不在於「發現成長股」——那人人都做得到——而在於三件事：月營收比季報早 1–2 個月揭露、涵蓋沒有法人追蹤的中小型股、以及用「市場尚未反映」的指標去找認知落差。

**而這些假設是否成立，由回測決定，不由直覺決定。**

## 設計原則

這個專案最花力氣的部分不是抓資料，是避免騙自己：

| 原則 | 做法 |
| --- | --- |
| **消除存活者偏誤** | 補抓已下市公司的營收與股價，回測母體包含當時存在、後來消失的公司 |
| **預先登記假設** | 回測前先寫下要驗證什麼、用什麼門檻、什麼叫成功，寫進 `docs/` 再跑，避免事後挑參數 |
| **數字由程式算** | LLM 只做文字解讀與分類，不計算任何數字、不挑選任何股票 |
| **誠實記錄失敗** | 回測沒有證明超額報酬的策略，報告就寫沒有。見 `docs/price_test_report.md` |
| **可重複執行** | 每個模組都可單獨重跑且 idempotent，中斷後接著跑不會產生重複資料 |

最後一條最容易被忽略：系統裡的估值功能在介面上明確標註「回測未證明有超額報酬，僅供參考」。做了但沒驗證出效果的東西，不會假裝它有效。

## 系統架構

```
┌─────────────────────────────────────────┐
│  collectors/  每日收集                    │
│  revenue   月營收      financials  季報   │
│  prices    股價        events      重訊   │
│  delisted  下市公司（消除存活者偏誤）      │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│  SQLite  data/revenue.db                 │
│  schema.sql 定義                          │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│  analysis/  分析與驗證                    │
│  metrics        成長指標計算               │
│  screen         篩選條件                  │
│  eps_estimate   下季/全年 EPS 推估         │
│  valuation      合理價（TTM EPS × 歷史PE） │
│  persistence    成長持續性檢定             │
│  price_test     股價淘汰測試（相對同業     │
│                 超額報酬、分數 IC）        │
│  unpriced_study 「尚未反映」研究            │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│  app/  Streamlit + Plotly 儀表板          │
│  排行榜 / 產業分布 / 個股詳情 / 重訊時間軸 │
└─────────────────────────────────────────┘

jobs/daily.py  →  Windows 工作排程器（支援錯過後補跑、程序鎖）
```

## 技術選型

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 執行環境 | 本機 Windows + 工作排程器 | 資料量不大，不需要雲端成本 |
| 資料庫 | SQLite | 單機單寫入者，不需要 server |
| 儀表板 | Streamlit + Plotly | 分析型介面，不值得為它寫前端 |
| LLM | 可切換介面封裝 | 只用於新聞分類與文字解讀，不碰數字 |
| 測試 | pytest | 每個 collector 與 analysis 模組都有對應測試 |

## 安裝

```bash
pip install -r requirements.txt
cp .env.example .env        # 填入 LLM API key 與通知設定
python -c "import sqlite3; sqlite3.connect('data/revenue.db').executescript(open('schema.sql').read())"
```

## 使用

```bash
# 每日收集 + 分析（排程會自動執行這支）
python -m jobs.daily

# 啟動儀表板
streamlit run app/main.py

# 註冊 Windows 排程
powershell -File jobs/register_task.ps1

# 測試
pytest
```

## 回測報告

分析結果都寫成報告放在 `docs/`，包含驗證方法、結果與結論：

| 報告 | 內容 |
| --- | --- |
| `price_test_report.md` | 股價淘汰測試：訊號相對同產業的超額報酬與分數 IC |
| `persistence_report.md` | 營收成長的持續性：這個月成長，下個月還會嗎 |
| `unpriced_study.md` | 「成長未反映」的定義與有效性檢驗 |
| `eps_estimate_report.md` | EPS 推估方法與對照去年同季、季節外推的誤差 |
| `valuation_report.md` | 合理價計算方式與回測結果 |
| `verification_sample.md` | 收集到的資料與公開揭露的人工比對抽樣 |
| `data_sources.md` | 資料來源、更新頻率與已知限制 |

## 資料來源與禮貌

公開市場資料。所有抓取都有請求間隔（MOPS ≥ 2 秒）、重試與指數退避、明確的 User-Agent，並遵守來源站台的 robots.txt。對明確封鎖爬蟲的來源不做批量抓取。

## 已知限制

- 月營收與季報都是落後指標，系統無法預測突發事件
- 回測區間 5 年，涵蓋的景氣循環有限
- 「市場尚未反映」的操作型定義仍在調整，見 `docs/unpriced_study.md`
- 估值模組的回測尚未證明超額報酬，介面上已標註僅供參考
